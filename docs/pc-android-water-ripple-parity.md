# PC / Android 雨滴波纹对齐

检查项目：`GameEditorProjects/DemoGame01` 的 `scenes/main.scene.json`。
该场景有 900 个雨滴，水面波纹寿命 10 秒，粒子波纹最短间隔 1.73 秒，合并距离 0.6。
雨滴的出生盒高度范围为中心上下各 50，中心 Y 为 4；水面平均 Y 为 1，因此许多粒子可以直接出生在水面深处。

## 差异与原因

| 项目 | 原 PC 编辑器 / GamePlayer | Android 当前主渲染路径 |
| --- | --- | --- |
| 雨滴触发条件 | 水面下方任意深度也算触水 | 仅水面附近的垂直接触窗口 |
| 波纹作用区域 | 缩放后的整块水面 | 中心周围 Size / 2 的世界空间圆形区域 |
| 触发间隔 | 空间格子键，粒子移动可以换键 | 粒子索引键 |
| 粒子销毁 | 深处出生的粒子立即销毁、随机重生 | 当前主路径不执行触水销毁 |
| 波纹池与波形 | 48 个槽位，共用衰减与波形 | 相同的 WaterSurfaceComponent 和槽位数量 |

PC 的事件量远大于 Android，连续替换最老的波纹；近处雨滴也能把人物波纹合并、移动并重置年龄。
因此设置较长寿命仍然无法保留人物波纹。问题来自事件生成和槽位竞争，波形衰减参数并没有不同的寿命配置。

## 修正

- 编辑器、PC GamePlayer 和 Android 主路径共用 `ParticleWaterRipplePolicy`：保持 Android 的接触窗口和局部波纹作用区域。
- 触发键包括水面、粒子系统和粒子索引；粒子移动不绕过间隔，多个发射器不共用索引节流。
- 合并距离只控制粒子波纹的合并，和时间节流分开。
- PC 仍遵守 `KillOnWaterContact`，但只在粒子真正接近水面时销毁，不再对深处出生的粒子制造重生循环。
- 波纹标记为粒子或人物／脚本来源；粒子波纹只合并和替换粒子波纹，新增人物／脚本波纹优先替换粒子波纹。
- 保持 48 个槽位、原波形、原寿命配置和原 GPU 上传格式。DemoGame01 项目文件未修改。

`Size / 2` 是 Android 原有的可见波纹区域，独立于水面 Transform.Scale 后的完整网格范围。
本次为了对齐既有 Android 效果保留该范围；人物碰撞及 PC 的粒子移除仍检查完整水面。

## 验证

回归测试读取项目实际参数，以固定随机种子、60 Hz、平面水面模拟 5 秒。Android 参考使用共享粒子模拟器与原 Android 触发／不销毁规则，因此数值是可重复模拟，非真机测量。

| 统计 | 结果 |
| --- | --- |
| 原 PC 波纹事件 | 5193 |
| 修正后 PC 波纹事件 | 133 |
| Android 规则参考事件 | 118 |
| 原 PC 深处出生造成的错误事件 | 3706 |
| 人物波纹经过 5 秒 | 仍有效，中心不变，年龄 5 秒 |

另有接触窗口对齐、发射器节流隔离、雨滴合并不重置人物波纹、波纹池溢出保护和正常到期测试。
